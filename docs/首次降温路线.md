# 首次降温路线与离线规划工具

适用：预期 GHz 频段 KID，E5071C 正向复数 S21，链路功率需要现场核算。当前版本不执行自动搜索、拟合或功率阶梯。

## 1. 设计表怎么使用

`python3 vna.py prepare 设计.xlsx` 读取指定表的 A:I：

| 原列名 | 导出字段 | 用途 |
|---|---|---|
| pixel_id | pixel_id | 设计标签，不是已经确认的实测峰身份 |
| f_target / Hz | f_target_hz | 目标设计频率 |
| f / Hz | f_model_hz | 模型预测频率；默认作为搜索中心 |
| f_error_hz / Hz | f_error_hz | 原表的设计误差，保留原义 |
| q_target / q / q_basic | 同名规范化字段 | 设计 Q 信息；不直接当作加载 QL |
| status / geometry_complete | model_status / geometry_complete | 源模型状态；不能当作实机验收 |

源 XLSX 的表名默认 `结果表`，可用 `--sheet` 指定。模板之外的表头不会猜单位或自动改列。公式单元格不计算，也不使用可能过期的缓存；请另存静态值副本。几何列和“设置与说明”中的文字不作为操作指令。

也支持 UTF-8 CSV，至少含 `pixel_id,f_target_hz`，单位 Hz；有 `f_model_hz` 就优先用它，缺失时回退目标频率并逐条标注依据。重复 ID、非有限数值或超出当前采集器频率范围的搜索窗口会停止准备。设计/导出文件不会自动上传 GitHub。

`source.json` 保存原文件名、SHA256、表名和行数；`design.csv` 保存本次输入行号。若再次导入导出的 CSV，新 source.json 指向该 CSV，原始 XLSX 的 source.json 仍应随旧 PREP 目录保留，形成追溯链。

## 2. 搜索计划的假设

默认：设计频率 ±2%、规划 QL 上限 100000、1601 点、每线宽 8 个采样间隔、相邻段重叠 10%。这些数值是可修改的搜索假设，尚未由器件验证。

- 频率裕量不从文件名的 Qc ±6% 推导；Qc 的容差与频率偏移不同。
- 表内 q、文件名 Qc 和实测 QL 不能互相替代。若文件名与表内数值不符，保留差异并由设计人员确认。
- 线宽近似 `f/QL`，每段按最低频率设置 `δf≤f_start/(QL_upper×8)`。比假设更高 Q 的窄峰仍可能漏掉。
- 相邻设计频窗先合并，再生成随频率变化的分段，避免对每个相互重叠的候选窗口重复扫描。
- ±2% 之外的实际谐振不在覆盖保证内。没有发现峰不等于芯片失效；需重新检查偏移范围、Q、信噪比和链路。
- 搜索跨越温漂时，拼接图不代表同一温度的静态频谱；一次完整搜索耗时先实测后估算。

例如需 ±5% 频率搜索，并采用更保守的 QL 上限：

```bash
python3 vna.py prepare "/路径/设计.xlsx" --margin-pct 5 --ql-upper 200000
```

测得单段扫频、传输、写盘合计 2 秒后，重建耗时估算：

```bash
python3 vna.py prepare "/路径/设计.xlsx" --seconds-per-segment 2
```

不填该参数时，耗时显示“未知”，不会假装能在一轮分钟级扫描中找全器件。修改假设会新建 PREP 目录，不覆盖旧版。

### 输出解释

- `准备结果.md`：人类可读摘要、明确假设、现场缺项与下一步。
- `plan.json`、`search_segments.csv`：建议搜索段。`power_dbm` 始终留空，状态 `PLAN_ONLY_NOT_EXECUTABLE`，不能直接交给 capture/monitor。
- `targets.csv`：设计频窗与约 20 条假设线宽的局部 Span 提示。该 Span 不是实测最优值。
- `site_review.json`：现场参数快照；填齐也不构成实机批准。
- `PREP_COMPLETE.json`：上述文件的 SHA256。准备中途停止时不写此完成标记。

## 3. 降温前与高温背景

先整理完整功率预算：`芯片读出功率≈VNA端口功率−输入总损耗`，同时核算输出放大链与 VNA/FSW 接收电平。各级数值要按频率和温级说明，未知量不能写成零。

在已确认的功率下保存链路背景。超导转变温度以上可能没有谐振；结合材料、温度与供电判断。初次可以保持未校准并保存原始复数 S21，之后再改善绝对传输和 Qi/Qc 精度。

校准参考面位于实际 DUT 连接的 SMA 电缆端，包含前面的 N→SMA 转接器。室温参考面不等于低温芯片参考面。含隔离器和放大器的单向链路不能直接套完整双端口反向扫描流程，详见 [操作说明](操作说明.md)。

## 4. 搜索、局部确认与功率验证

1. 总览用于确认背景与大尺度异常，不能替代密集搜索。1–3 GHz/1601 点的 1.25 MHz 网格可能漏窄峰。
2. 在选定温度平台，先验收少量分段，再按计划完整搜索；每段完整保存实际频率和 Re/Im，不仅保存拼接图。
3. 对候选峰作局部细扫，查看幅度、相位和复平面。先用约 10–20 条实测线宽的窗口、1601 点；IFBW 可从 100–300 Hz 起，根据噪声降低至 10–30 Hz。搜索阶段可先用 1 kHz。
4. 根据实测线宽调整 δf，重复扫描检查稳定性。扫描方向、点间稳定时间和接收滤波都可能影响线形。
5. 在稳定温度下，从已核算的低功率开始，以 2–3 dB 小步改变。比较 f0、QL、信噪比、线形、迟滞和链路压缩；异常停止升功率。
6. 实测峰与设计标签先作候选关联；制造偏移、峰碰撞或顺序交换时，不能仅按峰频率排序宣称已对应所有 pixel_id。

局部 Q 拟合需要另行开发和离线验证。未校准背景、复数电缆延迟和失配未处理时，不把拟合 Qi/Qc 当作高精度结论。一次单音 I/Q 也不能唯一恢复瞬时完整的 f0、Qi、Qc。

## 5. 参数确认后，进入固定窗口记录

一个目标或一个已确认的局部窗口先每 60 秒一次，变化快时试 10–30 秒；所有窗口的整轮采集与写盘必须有余量，不补扫积压。温漂导致谐振接近边缘时先保存并提示人工重定位。

原自主宏一次只记录一个固定窗口，参数变化会退出。它适用于确认后的长测，不负责多段搜索或自动跟踪。两扫之间的 Hold 可能降低激励，不能把这个条件当作稳定连续 CW。若将来需要持续偏置，应单独设计并验收。

记录每次扫频的开始/结束时间及对应温度日志。Python 的 `--temperature-k` 仅为人工起始值；VNA 原生时间曾未校准，不能直接当成已同步 UTC。原始数据、元数据、拟合与图分开保存。

基温先暗测 30–60 分钟，检查漂移和重复性，再延长。固定窗口采样率不等于连续噪声采样率；需要 PSD 时另作 I/Q 方案。

## 6. 后续 CW + FSW：独立阶段

先用 VNA 找到合适工作频点和功率，再让 Port 1 持续单音输出，KID 输出经隔离/放大链进入 FSW。先顺序切换接收机，不把 RF 口简单并联。

已有 FSW 查询设置为 32 MS/s、10 MHz I/Q；这是可行性信息，尚无该链路的光响应证据。拟从 PPS 每秒触发一次、每次 5 ms、约 1 ms 预触发起步，保存单次 I/Q 后再平均。单条 float32 I/Q 约 1.28 MB，100 条约 128 MB。

PPS 负责事件触发，10 MHz 负责共同频率参考。VNA 固定 CW 不随每个 PPS 重触发；原扫频宏必须停止。共用参考后仍要检查相对相位噪声、CW 连续性、FSW 过载、实际触发延迟和记录尾部。先做遮光但保留电触发等对照，排除串扰。

KID 的时间响应受 `τr≈QL/(πf0)` 及准粒子恢复等影响，不能把光脉冲宽度直接当作 KID 响应宽度。FSW 方案适合单工作频点验证，不代替整个 1–3 GHz 阵列的 RFSoC 多音读出。
