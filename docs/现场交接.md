# 现场接手：先从这里开始

适用版本：电脑工具 v0.3.0；VNA 内部宏仍为 v0.2.2。更新日期：2026-11-15。

目标是第一次降温时找到并确认 KID 谐振，再进行可靠的固定窗口记录。当前已完成采集/保存基础和离线首测规划，自动分段实测、Q 拟合与光脉冲采集仍需按路线开发、验收。

## 一、接手人需要拿到什么

1. 本仓库完整副本，含 `native/` 的可加载 VBA 项目和 `tests/`。电脑装 Python 3.10+，运行时不需要互联网或第三方包。
2. 设计 XLSX 原件，或本地交接包中的 `design.csv`、`source.json` 和整个 `PREP_...` 目录。真实设计、现场配置及测量数据单独传递，不依赖公共 GitHub 保存。
3. 制冷机输入/输出链路表：各段方向、频率、温级、损耗/增益、偏置、允许电平和记录依据。
4. 样品/装片对应关系、温度记录来源，以及仪器当前 IP/身份。旧 IP、盘符、剩余容量和 RF 状态都需要重查。

若拿到的是本地 ZIP，先读包内 `交接包说明.md`，核对版本和文件校验。不要把 `PREP_...` 误当成测量数据目录。

## 二、到现场前就能完成

终端进入项目目录，或双击 Mac 的 `启动.command` / Windows 的 `start.bat`。首次准备选菜单 **8**，输入设计表路径；现场参数暂缺时直接回车。

命令行等价操作：

```bash
python3 vna.py --version
python3 -m unittest discover -s tests -v
python3 vna.py prepare configs/design.example.csv
python3 vna.py demo --kind kid
```

示例设计和 demo 都是模拟内容，不能用于证明实际 KID 性能。`prepare` 不联网，只输出设计导入和搜索建议。

对真实表，路径含空格时加引号：

```bash
python3 vna.py prepare "/路径/设计.xlsx"
```

生成目录在 `data/PREP_.../`，先读 `准备结果.md`。`PREP_COMPLETE.json` 出现且校验匹配才是完整准备结果；没有它的文件夹可能是中断产物。原 XLSX 不修改。

### 现场参数表

复制 `configs/site.example.json` 为 `configs/site.local.json`，填写：

| 字段 | 现场填写依据 |
|---|---|
| sample | 实际样品/装片标识，以及覆盖哪些设计 pixel_id |
| input_loss_db | 输入方向总损耗；附各级频率/温度/方向明细 |
| output_gain_db | 输出净增益；附各级明细及压缩/最大输出检查 |
| source_power_dbm | 拟用的 VNA 端口功率，不是芯片功率 |
| max_source_power_dbm | 经芯片与接收链路预算复核的最高源功率 |
| chain_reviewed | 真实完成上述核算后才填 true |
| temperature_source | 温控器/日志来源、单位、采样间隔和时间基准 |
| design_q_kind | 确认表内 q 是 Qc、QL 或 Qi；未确认保留 unknown |
| operator / notes | 操作人，预算依据、时间偏差、接线和未解决事项 |

```bash
python3 vna.py prepare "/路径/设计.xlsx" --site configs/site.local.json
```

**填齐现场表仍只会得到离线计划，不会生成或解锁可执行采集配置。** 原有采集配置字段是 `power_dbm`、`max_power_dbm` 和 `chain_reviewed`，不要把现场表直接交给 capture。原程序源功率还限制在 −55 至 −20 dBm；需求超出时先重新评估和开发，不能只改一个限制数值。

## 三、到现场的操作顺序

| 顺序 | 接手人做什么 | 应留下的结果 |
|---|---|---|
| 1 | 核对链路、功率预算、样品、温度与时间基准 | 填写现场表和链路明细，缺项保持可见 |
| 2 | 保存仪器原状态，只读确认型号与配置 | 身份/设置快照，确认不是另一台同型号设备 |
| 3 | 断开 KID，接已确认耐受的无源器件，验证原单扫/保存/结束行为 | 完整原始 CSV、JSON、日志、verify 结果 |
| 4 | 开发并验收受监督的多段执行器，先 1 段，再 3 个重叠段 | 段编号、计划与实际轴、原始数据；异常不重触发 |
| 5 | 接低温链路，按约定温度平台搜索、局部确认和功率依赖 | 谐振候选、实测 QL/线宽与重复性，更新搜索假设 |
| 6 | 固定窗口后启用原 VNA 内部宏，先做短测 | 默认 D:\KID_DATA 下完整 RUN，导入/校验通过 |
| 7 | 再延长暗态记录；之后才开展 CW + FSW 光测试 | 分别验收长期运行、触发、噪声和真实光响应 |

原有无源单扫命令和网络接法在 [操作说明](操作说明.md)。这一步会设置 RF/扫频，只能在接线与功率确认后操作。不要一接上网络就运行 capture。

无局域网基础设施时可以电脑与 VNA 有线直连，或使用独立交换机；两端设在同一网段。离线指不依赖互联网，并不妨碍本地有线网络控制。仪器内部宏则在启动后不依赖电脑调度。

## 四、历史验证与当前缺项

| 能力 | 已有证据 | 仍待确认 |
|---|---|---|
| 网络单扫/短重复扫 | 旧仪器上无源 LPF 的有界短测通过 | 现场身份、电平、接线、长期稳定性 |
| VNA 内部记录 | 关闭 Mac 控制 TCP 后，D 盘完成 3 次短扫、数据完整、结束 RF OFF | 物理拔网线、长测、断电、当前 U 盘写入 |
| 默认目录 | v0.2.2 的默认/空白/取消等逻辑自检通过 | 现场人工菜单操作与当前磁盘状态 |
| 首测设计规划 | v0.3.0 离线导入、分段建议、缺项报告 | 搜索假设、实机多段执行、实测候选匹配 |
| Q 拟合与跟踪 | 尚未实现 | 离线算法验证后，再进入真实数据解释 |
| CW + FSW I/Q | 旧 FSW 查询到 32 MS/s、10 MHz I/Q 设置 | CW 连续性、触发、噪声、记录长度和光响应 |

历史证据见 [实机验证记录](实机验证记录.md) 和 [D 盘验收](D盘自主采集验收.md)。不要将离线测试、LPF 通过或仪器参数查询改写成 KID 通过。

## 五、遇到异常和交给下一位同事

- 断网/超时/数组异常后保留现有数据并停止，不自动重触发。无法确认 RF OFF 时，在前面板核对。
- 未发现谐振时先检查链路、供电、频带、网格和背景；不自动升功率。
- 不把固定窗口宏与 CW 光测试同时运行。原宏会改变扫描/触发，结束时关闭 RF，扫间 Hold 也可能改变读出占空比。
- 每次测试后复制完整运行目录到第二介质，记录代码提交号、样品、实际配置、接线改动、停止原因、RF 状态和下一步。
- 新同事或 AI 接手时依次读本页、[首次降温路线](首次降温路线.md)、[维护计划与验收](维护计划与验收.md)，再看代码；先核对现状，不凭旧聊天直接操作仪器。
