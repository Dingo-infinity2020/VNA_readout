# 集焓制冷机接口交接

适用范围：2026-11-19 核对的集焓 `DR system` / `DR_Project` 工控机版本。仓库提供独立只读查询脚本。VNA 采集流程尚未接入该遥测，也不控制制冷机。

## 接入路径

网线和 Tailscale 都用于到达 Windows 工控机。厂家 TCP 接口由 `DR_Project` 监听在工控机本机的 `127.0.0.1:9527`。从另一台电脑直接连接工控机的有线或 Tailscale 地址上的 `9527`，访问不到这个本机监听器。

已验证的路径为 **Mac → Tailscale → Windows OpenSSH → 工控机本地 TCP `127.0.0.1:9527`**。在工控机本地终端中也可直接执行同样的 TCP 查询。保持原厂端口仅监听本机。多台电脑日常看数时，可考虑由工控机定时采集，再给经授权的客户端提供独立只读接口。维护 SSH 与遥测访问分别授权，站点地址、账户、密钥和现场数据由本地交接保管。

## 已实测的只读查询

在仓库根目录执行。工控机本机用 Python 3.10+，远端方式只要求客户端有 Python 和 `ssh`，工控机使用 Windows PowerShell。

```text
py -3 cryostat_query.py
python3 cryostat_query.py --ssh coolab-ipc
python3 cryostat_query.py --ssh coolab-ipc --json
```

`coolab-ipc` 是示例 SSH 别名。使用远端方式前，在客户端的 `~/.ssh/config` 配置一次，替换以下占位符，并将工控机已核验的主机公钥放入指定的 `known_hosts` 文件：

```sshconfig
Host coolab-ipc
    HostName <工控机地址>
    User <Windows账号>
    IdentityFile <本机私钥路径>
    UserKnownHostsFile <已核验的known_hosts文件>
```

现场配置留在仓库外。脚本使用非交互式 SSH 并要求主机指纹匹配。

每次执行只发一次查询。默认输出带 UTC 时间的温度、压力与流量；`--json` 同时保留原始响应行，可供离线分析。默认查询超时为 10 秒，可用 `--timeout` 调整。响应不完整、字段数不符、只返回 `OK` 或超时均报错退出，不自动重试，也不返回旧值。

在工控机上连接本机端口，发送 ASCII `READ;ALL` 并以回车换行（CRLF）结束。该版本在连接后先发出 UTF-8 BOM，随后返回一行以逗号分隔的 **22 个字段**。

| 字段位置（从 1 开始） | 含义 |
| --- | --- |
| 1–16 | 温度通道 T1–T16，单位 K |
| 17–21 | G1–G5 压力，单位 mbar |
| 22 | 流量，单位 L/min |

解析结果中，`NaN` 和温度字段中的 `0` 都记为未知（JSON 为 `null`），原始响应仍保留原值。压力和流量的有效零值保留。混合室对应的通道需要用通道表和界面现场核对。

厂家说明书不同章节使用了 `READ;DATA`、`READ;ALL` 和 `READ;STATUS`。本次实测 `READ;ALL` 返回测量值，另两条均只返回 `OK`。工控机源码的读取分支也只为 `READ;ALL` 构造数据。升级软件后需重新确认可用查询和返回字段布局。

## 控制能力与验收边界

工控机源码有 `OPEN` 和 `CLOSE` 控制分支，映射到 V1–V16 阀门、机械泵、两台分子泵、安捷伦泵和 F100 脉管机。**这次仅核对源码并读取数据，没有执行任何开关动作。** `OK` 不提供实际设备状态，不能作为硬件动作回执。本次也未确认泵阀状态、当前程序模式、联锁或故障停机行为。

实机控制需另行安排，由现场操作员核对工况和厂家操作流程，并用工控机界面或独立状态读回确认结果。接口超时或动作结果不明时，现场确认后再决定下一步。VNA 采集、准备和 CI 流程不应隐式发送制冷机控制命令。

## 与降温扫频关联

首次降温前，核对混合室的通道、单位、工控机日志时区和相对 VNA 时钟的偏差。现场保留原始遥测、采集时间和版本，再与每次扫频的起止时刻对应。缺失或过期温度保持未知。VNA 的 `--temperature-k` 是人工录入的起始标记，不能代替这套遥测。采集阶段见 [首次降温路线](首次降温路线.md) 和 [操作说明](操作说明.md)。
